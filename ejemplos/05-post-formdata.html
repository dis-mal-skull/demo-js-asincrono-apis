Enviar datos también es conversación

Un GET pide; un POST envía. Completa el formulario y el servidor local responderá con el resumen de lo recibido, sin base de datos y sin frameworks.

No escribas el Content-Type

Al pasar un FormData, el navegador genera el boundary y la cabecera multipart. Si la fijas manualmente, el servidor no podrá separar los campos.

El viaje completo

Del formulario al texto de respuesta

El navegador serializa, envía, espera y devuelve. El mismo endpoint funciona con Node y con PHP.

post.js · fetch + FormData 
const formulario = document.querySelector("form");
const datos = new FormData(formulario);

const respuesta = await fetch("../test.php", {
  method: "POST",
  body: datos,
});

const texto = await respuesta.text();

if (respuesta.ok) {
  salida.textContent = texto;
} else {
  console.error("Error HTTP", respuesta.status);
}

La validación ocurre dos veces

En el navegador, para dar respuesta inmediata; en el servidor, porque nunca se confía en el cliente. Aquí el servidor limpia etiquetas y recorta a 400 caracteres.

¿Qué diferencia hay entre FormData y JSON?

FormData imita el envío clásico de un formulario y admite archivos sin conversión. JSON es más cómodo para APIs y estructuras anidadas, pero requiere JSON.stringify y el encabezado Content-Type: application/json.
