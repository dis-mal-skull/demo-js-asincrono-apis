El orden de las cosas

JavaScript ejecuta una tarea a la vez, pero no espera sentado. Descubre cómo el event loop reparte el trabajo y por qué el orden real casi nunca es el que escribiste.

Qué observar

El setTimeout de 0 ms no se ejecuta de inmediato: entra a la cola de macrotareas y espera a que la pila y las microtareas terminen.

No confundas programar con ejecutar

setTimeout(fn, 0) no significa “ahora mismo”. Significa “lo antes posible, cuando la pila esté libre”.

La teoría detrás de la demo

Una pila, dos colas y un bucle

El motor de JavaScript ejecuta una función a la vez. Las tareas asíncronas no interrumpen: se encolan y esperan su turno.

orden.js · setTimeout 
console.log("1 · síncrono");

setTimeout(() => {
  console.log("4 · macrotarea");
}, 0);

Promise.resolve().then(() => {
  console.log("3 · microtarea");
});

console.log("2 · síncrono");

// Orden real: 1 → 2 → 3 → 4
callbacks.js · datos encadenados 
function fakeGetUser(callback) {
  setTimeout(() => {
    callback({ id: 1, nombre: "Ana" });
  }, 400);
}

function fakeGetPosts(usuarioId, callback) {
  setTimeout(() => {
    callback([{ id: 10, titulo: "Event loop" }]);
  }, 500);
}

fakeGetUser((usuario) => {
  console.log("Usuario:", usuario.nombre);

  fakeGetPosts(usuario.id, (publicaciones) => {
    console.log("Publicaciones:", publicaciones.length);
  });
});

El recorrido de una tarea

  1. Pila de llamadasEjecuta el código síncrono, función por función.
  2. MicrotareasPromesas y queueMicrotask. Se vacían antes de pintar.
  3. MacrotareassetTimeout, eventos y peticiones. Una por vuelta del bucle.
  4. RenderEl navegador pinta cuando las colas prioritarias están vacías.
Regla mental

Todo lo síncrono termina primero. Después las microtareas. Después, una macrotarea. Y el ciclo vuelve a empezar.

¿Por qué el callback hell es un problema?

Porque cada paso vive dentro del anterior: el código crece hacia la derecha, el manejo de errores se repite y reutilizar una etapa se vuelve difícil. Las promesas y async/await resuelven justamente esa legibilidad.

¿setTimeout(0) es instantáneo?

No. El navegador aplica un mínimo de temporización y, sobre todo, espera a que la pila de llamadas esté libre. En la práctica puede tardar 1 ms o más.
