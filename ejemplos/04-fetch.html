Del código a la pantalla

Dos awaits, un contrato claro

El primero obtiene la respuesta; el segundo convierte el cuerpo en un objeto de JavaScript. Ninguno bloquea la interfaz.

fetch.js · con timeout 
const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 15000);

try {
  const response = await fetch(url, {
    signal: controller.signal,
    headers: { Accept: "application/json" },
  });

  console.log("ok:", response.ok);
  console.log("status:", response.status);

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  const perfil = await response.json();
  pintarPerfil(perfil);
} finally {
  clearTimeout(timer);
}
El cuerpo también es un flujo

response.json() lee el cuerpo una sola vez. Si necesitas el texto crudo y el JSON, clona antes: response.clone().

Qué puedes leer de la respuesta

PropiedadPara qué sirve
okBooleano: estado 200–299.
statusCódigo HTTP numérico.
headersCabeceras como content-type.
urlURL final tras redirecciones.
bodyFlujo legible una sola vez.
¿Cuándo usar AbortController?

Cuando el usuario cambia de vista, cuando llega una respuesta vieja que ya no importa o cuando quieres imponer un tiempo máximo. Cancelar una promesa de fetch lanza un AbortError.

¿Y si la API bloquea por CORS?

La consola mostrará un error de red, no un estado HTTP. La solución no está en tu JavaScript: el servidor debe enviar Access-Control-Allow-Origin o debes consumir los datos desde un backend propio.
